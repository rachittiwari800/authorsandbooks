# Assignment implementation brief

The solution prioritises a working, secure ticket lifecycle over external deployment and visual polish. It retains the existing React, Express, and SQLite stack, preserving seeded publishing records and the existing dashboard while completing the author and support-admin workflows.

Identity and authorization are server-managed. Bcrypt hashes demo passwords, role checks protect every private API, ticket ownership is verified before author detail is returned, and author message responses are limited to public replies. SQLite provides relational persistence for tickets, messages, AI recommendations, administrative overrides, and sessions. The dataset seed is idempotent and production startup does not create local demo accounts.

AI is an optional backend capability rather than a dependency for support operations. OpenAI `gpt-4o-mini` is the default because it is a cost-conscious choice for short structured triage and concise support drafts; the model is configurable. Prompts pair the relevant BookLeaf policy with only the ticket, author name, selected book facts, and at most five bounded recent public messages—not the entire history or dataset. Category-specific guidance follows the supplied examples for royalty cycles and transparent breakdowns, urgent ISBN review, verified print reprints, distribution sync, truthful production updates, and metadata edits. Outputs are checked against canonical values and empathy/concern requirements. The system does not claim that staff performed an escalation or re-sync action it cannot execute. Provider failures produce explicit fallback indicators and require human review without preventing ticket creation. Drafts remain staff-only until an administrator deliberately sends a public response.

Within the assignment timeline, SQLite and polling were selected to avoid an unnecessary database migration and real-time infrastructure. The trade-off is that SQLite storage assumes a single application instance and polling is less immediate than SSE/WebSockets. Attachments are selectable locally but are not uploaded. No hosted deployment was performed because deployment credentials and a target environment were not provided.

For production scale, move to managed PostgreSQL with schema migrations and a shared Redis/session store, add controlled staff-account provisioning and audit retention, secure file storage with malware scanning, rate limits and observability, and replace polling with authenticated SSE or WebSockets.
